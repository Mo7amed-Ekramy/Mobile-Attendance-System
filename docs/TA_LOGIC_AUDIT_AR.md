# مراجعة منطق حساب المعيد

التاريخ: 14 نوفمبر 2026.

هذه مراجعة للواجهة ومسارات الـAPI والصلاحيات وتدفق البيانات الحالي. تتضمن إصلاحات منفذة، واختبارات فعلية، وفحصًا للواجهة بحساب المعيد. قرر صاحب المشروع أثناء المراجعة أن الميدتيرم والفاينال يخصان الدكتور؛ المعيد يعمل على أعمال سكاشنه فقط، ويظل نشر النتائج للدكتور.

## النطاق الصحيح بعد التعديل

| المجال | سلوك المعيد |
|---|---|
| الدخول | حساب فعال وجلسة صالحة؛ لا اختيار دور أو تجاوز للمصادقة |
| المقررات والسكاشن | المقررات المسندة له فقط، وداخلها سكاشنه فقط |
| اختيار السكشن | يحدد نطاق الطلاب والحضور والدرجات والتقارير |
| حضور السكشن | إنشاء كشف لسكشن به طلاب، حفظ مسودة، استكمالها، ومراجعة واعتماد كل الطلاب |
| حضور المحاضرات | الاطلاع على حضور طلاب السكشن المختار؛ فتح المحاضرة والـQR والإغلاق للدكتور |
| لائحة الدرجات | قراءة اللائحة؛ الإنشاء والتعديل والاعتماد للدكتور |
| التقييمات اليدوية | كويز ورقي أو تكليف أو مشروع للسكشن؛ الميدتيرم والفاينال للدكتور |
| الكويز الإلكتروني | إنشاء لسكشن مسند له، تحضير أو جدولة أو فتح، وإلغاء قبل أي محاولة أو إغلاق مبكر |
| نتائج الكويز الإلكتروني | تصحيح تلقائي وعرض فقط حتى إغلاق الكويز؛ بعد الإغلاق يمكن الرصد أو التصحيح ضمن الصلاحية |
| نشر النتائج | للدكتور فقط، وبعد إغلاق الكويز الإلكتروني إن كان التقييم مرتبطًا بكويز |
| تصحيح درجة منشورة | يتطلب سببًا، وتبقى النسخة المنشورة السابقة حتى يعيد الدكتور النشر |
| التقارير والطباعة | الطلاب المسجلون في السكشن المصرح به، مع حضور ودرجات منشورة ونطاق واضح |
| بنك الأسئلة | بنك مشترك للمقرر؛ إضافة سؤال لا تغير النسخ المحفوظة في كويزات سابقة |
| الإشعارات والإعدادات | إشعارات الحساب وتفضيلاته؛ دليل معيدي المقرر يظهر للدكتور فقط |

## المشاكل التي أُصلحت

1. **إتاحة الميدتيرم والفاينال للمعيد:** أُزيل النوعان من نموذج إنشائه، ومن قائمة تقييماته، وأصبح إنشاء أو رصد هذه الأنواع من طلب API مباشر مرفوضًا بـ403. يظل الدكتور قادرًا عليهما.
2. **تعديل ونشر درجات الكويز قبل انتهاء التصحيح:** كانت الدرجات اليدوية قابلة للاستبدال عند تسليم الطالب. أصبح سجل المسودة والكويز المجدول أو النشط للعرض فقط. السيرفر يرفض التعديل والنشر قبل الإغلاق، والواجهة تلتزم بحالة `editable` وسبب المنع. الكويز الورقي اليدوي لا يتأثر بهذه القاعدة.
3. **اختلاف نطاق المحاضرة عن السكشن المختار:** كانت قائمة الحضور تحسب السكشن المحدد، بينما التفاصيل تعرض جميع سكاشن المعيد. أصبحت التفاصيل تقبل نطاق السكشن وتتحقق منه وتعيد صفوفه فقط. يظل الوصول لسكشن غير مسند أو غير مطابق للجلسة مرفوضًا.
4. **كشف حضور فارغ غير قابل للاعتماد:** أصبح زر الإنشاء ينتظر معرفة الطلاب، ويتوقف عند خلو السكشن، ويرفض السيرفر إنشاء كشف فارغ حتى من عميل قديم.
5. **تكرار التنقل في سكاشني:** المقرر عنوان تجميعي غير قابل للضغط، والسكشن يفتح مساحة عمله مباشرة. البحث يشمل أرقام السكاشن وأقسامها، واختيار المقرر والسكشن يحدث معًا لتجنب إعادة تحميل مؤقتة لنطاق آخر.
6. **مسودات تختفي وسط المحاضرات الحديثة:** الرئيسية تطلب مسودات السكشن مباشرة، وتعرض استكمال آخر كشف محفوظ، مع رابط لكل المسودات وقائمة قابلة للتصفية والتنقل بين الصفحات. محاضرات الدكتور ليست مهام رصد للمعيد وتوصف بأنها للاطلاع فقط.
7. **شاشة دليل المعيدين غير اللازمة للمعيد:** أُخفيت من حسابه، مع بقاء تقارير سكشنه. تسمية التقرير في حسابه أصبحت «تقرير السكشن».
8. **تداخل موضع التمرير بين التبويبات:** أصبح التخزين مستقلًا حسب الحساب والتبويب والمقرر والسكشن، فلا يبدأ تبويب جديد عند موضع تمرير محفوظ من تبويب آخر.
9. **خيارات كويز تؤدي إلى سجل غير مناسب:** مسودات الكويز والمجدول والملغى لا تفتح محرر درجات. إنشاء الكويز والتقييم لا يتاح عندما لا توجد بنود تقييم في اللائحة. توضيح أن بنك الأسئلة مشترك، وتمييز الكويز الورقي عن الإلكتروني.
10. **هوفر سطر الوضع الداكن:** أصبح السطر غير قابل للضغط، والسويتش نفسه هو وسيلة التغيير، مع بقاء تسمية قابلة للقراءة بأدوات الوصول.
11. **التباس اسم المعيد وعدد الطلاب:** بيانات مساحة عمل السكشن تصف الاسم صراحة بأنه «المعيد»، وعدد الطلاب بحقل منفصل.

## التحقق المنفذ

- `flutter analyze --no-pub`: بدون ملاحظات.
- `flutter test --no-pub`: 55 اختبارًا ناجحًا، تشمل التنقل والصلاحيات المعروضة وحماية الإدخال ونطاق السكشن والـQR والتقارير.
- اختبارات `server/test_api.py`: 24 رحلة تكامل ناجحة على PostgreSQL، بينها خمس حالات جديدة لحدود المعيد ودورة الكويز والمسودات والسكاشن الفارغة.
- `tool/role_checks/ta_api_audit.py`: 66 حالة API خاصة بالمعيد ناجحة. التفاصيل في [نتائج الفحص](../review/ta-logic-api-results.json).
- تجارب الكتابة في اختبارات السيرفر وقائمة فحص الـAPI استخدمت قواعد مؤقتة مستقلة تُحذف بعد الاختبار؛ لم تُنشأ بيانات تجريبية في قاعدة التطبيق المستخدمة للمراجعة.
- فُحصت الواجهة الفعلية لحساب المعيد، ومنها الإعدادات ودليل السكاشن والانتقال المباشر لمساحة عمل السكشن.

أوامر إعادة التحقق من مجلد `mobile`:

```powershell
flutter analyze --no-pub
flutter test --no-pub
.\server\.venv\Scripts\python.exe -m unittest discover -s server -p test_api.py -v
.\server\.venv\Scripts\python.exe tool/role_checks/ta_api_audit.py
```

## حدود وظيفية باقية

- تصحيح الحضور بعد الاعتماد أو إغلاق المحاضرة لا يملك دورة طلب وموافقة حاليًا؛ السجل الرسمي يبقى للعرض فقط. بناء مسار التصحيح يحتاج تحديد المسؤول عن الموافقة وأثرها على النتائج.
- حفظ المعيد للدرجات يجعلها مسودة تنتظر نشر الدكتور. لا يوجد زر مستقل لإرسال «جاهز للمراجعة» أو حالة اعتماد جديدة.
- اختيار أسئلة الكويز عشوائي بحسب العدد من البنك المشترك، وليس اختيارًا يدويًا لسؤال بعينه. تعديل أسئلة البنك وأرشفتها ليستا متاحتين حاليًا.
- مراجعة الويب لا تثبت عمل كاميرا جهاز فعلي أو إرسال إشعارات خارج التطبيق؛ هذه ليست من تدفقات حساب المعيد التي جرى اختبارها هنا.
